

## 文件夹重构任务

除非特别说明，我都是以项目文件夹 (path = '../ci-policy') 为根目录进行说明。

1. 目前 ./lectures 文件夹存放各章节讲义文件。但是各章的附录文档我现在做的有点乱。
   - 一类是实操代码：'./lectures/appendix' 放置了 Chapter 5-7 的附录，主要包括 .ipynb 和 .do 文档，目的是为了让学生课后可以演练的。我的问题是这个文件夹是维持现在的这种结构，还是把它放在 '../notebook' 下更合适？
   - 另一类放在了 '../resources' 文件夹下。你可以扫描一下这个文件夹的内容，有一些是属于实操代码类的，比如 '../resources/heckman/heckman_practical_notes.ipynb'，还有一些是扩展阅读文献，如 '../resources/heckman/appendix_heckman_selection_literature.qmd'。我觉得后者更像是标准的附录文档。
   我的想法是把那些实操里的代码都统一放到notebook文件夹里。而把那些真正的附录都梳理好，放在 './lectures/appendix' 中，供学生查阅和参考。你觉得这个方案是否可行？有没有更好的办法？

2.  ./lectures/code-data 文件夹本来我是想放一些让学生演练的数据和代码。当然在现有的讲义里，目前还没有涉及到使用这个文件夹。你扫描一下这个文件夹的内容，考虑一下。怎么使用这里面的内容以及把它放在什么地方比较合适？
3. ./cases 文件夹本意是对着第一章和第二章的内容放一些政策冲击的案例。但是我不想把这些部分的内容写的太过细致，因为它跟我这本书的定位好像有所偏离。所以我的想法是把他们作为第一章和第二章的附录。现在为了尽可能的保持项目目录的简洁，我想把这个文件夹里面的内容拆到附录 ('./lectures/appendix') 里面去。
4. ./scripts 这个文件夹感觉没什么用，应该可以把它删掉。
5. ./task-prompt 这个文件夹其实挺有用的，我是在撰写之初是透过这个文件夹来制定计划以及每一章的计划。我想也把它公开，以便于有一些学员里边他们想自己去讲义。甚至有一些学员是老师，他们也想按照我的模式来备课，我觉得可以提供给他们做参考。但是这个文件夹里边的这些文件的名称有点乱，似乎看不出先后顺序，有些内容写的也比较的繁琐或者是不严谨，你来帮我判断一下如何给这些文件做统一的命名，另外也帮我确定一下里边的这些具体的文字内容是不是需要修改。
6. ./temp-box 是我逐章写作的过程中存放这些过程文档的。因为在写作的过程中，我会同时使用codex和cloud code两个agent来做一个工作，有的时候我生成两个版本，会让他们彼此做比对，然后再做合并。你觉得这个文件夹我要怎么处理？是选择公开还是把它们只保留在本地而不发布到远程的仓库里。另外这个文件夹的名称可能也需要优化一下，否则的话包含 'temp' 这个关键词，随后可能会不小心把它删除掉，但是我本意是不想删除这个文件夹的。
7. 用 quarto render 编译后，我发现有这个文件夹 '.\docs\temp-box' 感觉不太舒服。'temp-box' 应该换个名字。
8. 其他文件夹和2级甚至子文件夹的这个安排，你统一帮我做个规划吧。

## 章节编号问题

- 「讲义」部分各章可以按顺序编号，但「附录」部分我建议不用顺序编号，可以参考 <https://lianxhcn.github.io/ds2026/> 的做法，附录可以用字母或者其他方式标识，而不必严格按数字顺序。
- 讲义之前的部分，比如前言、导读等，可以不用顺序编号，同时加上表情符号，比如 📖、📝 等，参见 https://lianxhcn.github.io/ds2026/
