# Codex 总任务说明：ci-policy 讲义项目

## 1. 项目定位

本项目名称为 `ci-policy`。它是一套一天课程的在线讲义，不是一本完整计量经济学教材，也不是因果推断方法百科。

课程主题是：

> 因果推断：政策评估中的识别思维与实证设计

讲义最终通过 GitHub 仓库和 GitHub Pages 发布。学员可以在线阅读，也可以 fork 仓库后在本地运行 Notebook、复现代码和扩展练习。

## 2. 核心写作主线

本讲义必须围绕政策评估研究设计展开。所有章节都服务于以下主线：

```text
政策目标 → 政策实施机制 → 数据形成机制 → 识别威胁 → 研究设计 → 估计方法 → 结果解释
```

这意味着：

- 不从方法定义开始；
- 不按 DID、RDD、IV、Heckman、SCM、DDML 等方法并列铺开；
- 不把讲义写成工具命令教程；
- 每一种方法都必须从政策评估中的具体问题引出。

例如：

- 当样本不是随机出现时，才引出样本选择、自选择和 Heckman 思维；
- 当处理组和对照组需要构造反事实时，才引出 DID、DDD、事件研究和 SCM；
- 当遗漏变量具有个体、时间、行业、地区等结构时，才引出固定效应、HDFE 和 IntFE；
- 当控制变量与结果变量、处理变量之间存在复杂非线性关系时，才引出 FWL 和 DDML；
- 当仍然担心未观测遗漏变量时，才引出敏感性分析。

## 3. 课堂时间约束

本课程只有一天：

```text
上午 3 小时
下午 3 小时
```

因此正式讲义正文必须服务课堂讲授，不能写成无限扩展的教材。方法细节、经典论文、延伸阅读和复现材料应放入附录、资源页或课后任务中。

课堂主讲内容集中在以下 7 章：

```text
第 1 章 政策评估从政策目标开始
第 2 章 政策如何进入数据：处理组、对照组与政策时点
第 3 章 谁被我们看见了：样本选择、自选择与 Heckman 思维
第 4 章 遗漏变量如何进入模型：控制变量、固定效应、HDFE 与 IntFE
第 5 章 如何构造反事实：DID、DDD、事件研究与合成控制
第 6 章 控制关系不再线性时：FWL、DDML 与设定偏误
第 7 章 从论文阅读到复现：AI 和 Agent 如何帮助继续学习
```

扩展内容包括：

```text
第 8 章 扩展阅读：书籍、连享会资料与在线课程
附录 A 可复现经典论文清单
附录 B Stata / Python / Quarto 环境说明
附录 C 课堂练习与课后任务
```

## 4. 仓库目录规则

正式发布目录包括：

```text
lectures/      正式讲义章节
notebooks/     可运行 Notebook
cases/         正式案例材料
resources/     公开资源索引、书单、推文清单、论文清单
refs/          BibTeX、DOI、参考文献资料
figs/          项目内图片，尤其是 Notebook 自动生成图片
scripts/       可复现脚本
data/          可公开数据、模拟数据和数据说明
exercises/     课堂练习和课后任务
```

本地非发布目录包括：

```text
refers/        老师提供的本地素材库，不提交 GitHub
working/       Codex 过程文件，不提交 GitHub
```

`refers/` 与 `working/` 必须加入 `.gitignore`。

## 5. 素材读取规则

第一轮只读取：

```text
task-prompt/
refers/_active/
```

不要递归读取：

```text
refers/_reserve/
refers/_archive/
```

如果你认为 `_reserve/` 中某个目录可能有用，应在 `working/reserve_reading_requests.md` 中说明：

- 需要读取哪个目录或文件；
- 它可能服务哪一章；
- 读取它的理由；
- 是否可以只读取其中的 `.md`、`.qmd`、`.ipynb` 或少量数据文件。

等待确认后再读取。

## 6. 第一轮任务范围

第一轮只做素材盘点和章节映射，不写正式正文。

需要生成：

```text
working/materials_inventory.md
working/chapter_material_map.md
working/missing_materials.md
working/reserve_reading_requests.md
working/next_questions.md
working/first_round_summary.md
```

每份材料都要判断：

- 适合哪一章；
- 是否适合直接改写；
- 是否只适合作延伸阅读；
- 是否适合转化为 Notebook 示例；
- 是否适合做案例材料；
- 是否应暂时忽略；
- 是否需要后续补充资料。

## 7. 写作风格底线

正式讲义要采用中文学术讲义风格：

- 朴实、准确、直接；
- 从读者真实困惑切入；
- 不堆叠术语；
- 公式服务解释，不做过度推导；
- 每章只保留 1–2 个核心例子；
- 代码示例必须说明看哪一行结果、如何解释；
- 中英文混排时加空格；
- 所有括号使用半角模式；
- 命令名、变量名、函数名用 `code` 格式。

## 8. 第一轮禁止事项

第一轮不要做以下事情：

- 不要撰写正式讲义；
- 不要修改 `refers/` 原始材料；
- 不要把 `refers/` 或 `working/` 中的路径写入正式章节；
- 不要复制大段旧讲义正文；
- 不要读取完整复现包源码；
- 不要读取 `.zip`；
- 不要读取大量 `.html` 和 `.pdf`；
- 不要把讲义整理成方法清单。
