# Codex 写作规则更新：Quarto 讲义样式、交叉引用与案例使用

本文件用于更新 `ci-policy` 项目的写作规则。请将本文件放入：

```text
ci-policy/task-prompt/codex_update_writing_rules_v1.md
```

并在后续第三轮正文写作任务中要求 Codex 先读取本文件。

## 1. 当前任务背景

本项目是一套可复用的在线讲义，主题为：

```text
因果推断：政策评估中的识别思维与实证设计
```

讲义后续可能用于不同课程和暑期班，因此不要写成某一天、某个学校、某个班级的专属课件。

本文件新增以下写作规则：

1. 书稿要适合直接作为在线讲义和课堂展示使用；
2. 3–5 项并列或递进内容优先改为列表；
3. 控制排比句长度；
4. 使用 Quarto callout；
5. 所有公式、图表、表格、章节标签必须使用更细的唯一前缀；
6. 第一章要明确扣住「因果推断：政策评估中的识别思维与实证设计」这一主题；
7. Lane (2025) 是主线案例，但不能压倒国内政策辅助案例。

## 小括号格式规则

正式书稿中的所有小括号必须使用半角模式：

```text
正确：( )
错误：（ ）
```


## 2. 输出格式规则

正式章节统一使用 `.qmd` 格式。

原因：

- 支持公式编号；
- 支持交叉引用；
- 支持 callout；
- 后续插入代码块、图表、练习更方便；
- 适合 Quarto render 生成在线讲义。

除非有明确理由，不要使用 `.md` 写正式章节。

## 3. 列表使用规则

本讲义会直接用于课堂讲授，因此正文不能全部写成长段落。

遇到以下情况，优先使用列表：

- 3–5 个并列判断；
- 3–5 个递进步骤；
- 3–5 个常见误区；
- 3–5 个政策评估检查项；
- 3–5 个案例对比；
- 3–5 个章节小结。

例如：

```markdown
一个政策评估问题至少要回答五个基础问题：

1. **政策为什么出台？**
2. **政策作用于谁？**
3. **政策通过什么工具发挥作用？**
4. **政策希望改变什么结果？**
5. **政策实施是否具有选择性？**
```

不要把这类内容写成长段落。

## 4. 排比句控制规则

排比句可以使用，但要克制。

规则：

- 一组排比最多 3–4 项；
- 超过 4 项时，改为列表；
- 如果内容存在明确顺序，改为编号列表；
- 如果内容是平行关系，改为项目符号列表；
- 不要在一段话中连续堆叠多个排比句。

错误示例：

```text
如果政策目标模糊，结果变量就会摇摆；如果政策对象不清楚，处理组就会含混；如果政策时点无法界定，事件研究就会失去基础；如果政策实施具有选择性，简单比较就会混入选择偏误；如果政策影响存在外溢，单个企业层面的回归又可能遗漏机制。
```

更合适的处理：

```markdown
如果前期研究设计没有想清楚，后续方法选择很容易失焦：

- 政策目标模糊，结果变量就会摇摆；
- 政策对象不清楚，处理组就会含混；
- 政策时点无法界定，事件研究就会失去基础；
- 政策实施具有选择性，简单比较就会混入选择偏误。
```

## 5. Quarto callout 使用规则

可以酌情使用 Quarto callout，但不要滥用。

建议类型：

### 5.1 `.callout-note`

用于本节要点、概念说明、小结。

```markdown
::: {.callout-note}
## 本节要点

政策评估首先要明确政策目标、政策对象和政策工具，然后再讨论变量、样本和方法。
:::
```

### 5.2 `.callout-warning`

用于常见误区、识别风险、方法误用。

```markdown
::: {.callout-warning}
## 常见误区

看到分批政策就直接使用 DID，容易忽略政策对象是否可比、政策时点是否清楚、处理效应是否异质。
:::
```

### 5.3 `.callout-tip`

用于课堂讨论、操作建议、写作提示。

```markdown
::: {.callout-tip}
## 课堂讨论

同一项政府引导基金政策，如果研究目标分别是融资约束、企业创新和产业链韧性，结果变量应该如何变化？
:::
```

### 5.4 `.callout-important`

用于全章核心命题或关键判断。

```markdown
::: {.callout-important}
## 核心问题

对于已经接受政策处理的对象，我们如何构造它在没有政策时的可信反事实？
:::
```

使用原则：

- 每章 callout 不宜过多；
- 每个 callout 必须服务授课节奏；
- 不要把普通正文都放进彩色框；
- 同一小节不要连续出现多个 callout。

## 6. 公式编号与交叉引用规则

所有正式公式必须编号，并使用更细的标签，避免将来与其他讲义合并时重复。

标签格式：

```text
{#eq:cipolicy-章节关键词-公式关键词}
```

示例：

```markdown
$$
Y_{it} = \alpha + \beta D_{it} + X_{it}'\gamma + \mu_i + \lambda_t + \varepsilon_{it}
$$ {#eq:cipolicy-did-twfe}
```

正文引用：

```markdown
式 @eq:cipolicy-did-twfe 展示了包含个体固定效应和时间固定效应的基本 DID 设定。
```

不要使用过短标签，例如：

```text
{#eq-twfe}
{#eq-did}
{#eq1}
```

这些标签后续容易与其他内容冲突。

## 7. 图表与章节标签规则

图、表、练习、案例也要使用唯一前缀。

### 7.1 图标签

格式：

```text
{#fig:cipolicy-章节关键词-图关键词}
```

示例：

```markdown
![政策评估工作流](../figs/concept/policy_workflow.png){#fig:cipolicy-intro-workflow}
```

引用：

```markdown
图 @fig:cipolicy-intro-workflow 展示了本讲义的基本工作流。
```

### 7.2 表标签

格式：

```text
{#tbl:cipolicy-章节关键词-表关键词}
```

示例：

```markdown
| 政策目标 | 可能结果变量 |
|---|---|
| 融资约束 | 融资成本、贷款可得性 |
| 创新激励 | 专利、研发投入 |

: 政策目标与结果变量示例 {#tbl:cipolicy-target-outcome}
```

引用：

```markdown
表 @tbl:cipolicy-target-outcome 展示了政策目标如何影响结果变量选择。
```

### 7.3 练习标签

格式：

```text
{#exr:cipolicy-章节关键词-练习关键词}
```

如果 Quarto 当前配置不支持自定义练习交叉引用，可以先用普通小节标题和 TODO 标记，不要强行复杂化。

## 8. 第一章主题扣题要求

第一章开头必须明确扣住本讲义主题：

```text
因果推断：政策评估中的识别思维与实证设计
```

建议表达：

```markdown
本讲义的主题是「因果推断：政策评估中的识别思维与实证设计」。这里的重点不是记住更多模型名称，而是理解一项政策如何被转化为可评价、可估计、可解释的研究问题。
```

第一章必须讲清楚：

- 政策评估为什么不能从模型开始；
- 因果推断的核心困难是反事实不可观测；
- 实证设计的任务是为缺失的反事实寻找可信替代物；
- 后续方法都服务于这个目标。
