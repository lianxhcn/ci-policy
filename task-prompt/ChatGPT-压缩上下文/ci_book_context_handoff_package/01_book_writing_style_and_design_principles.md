# 全书写作风格与设计原则

## 基本定位

本书不是资料索引，不是命令手册，也不是只堆公式的计量讲义。它是一套围绕政策评估展开的实证研究设计讲义。

读者阅读这份讲义，是希望获得一个完整脉络：每个模型在什么实证背景下被提出，解决什么问题，适用于什么场景，和现有模型有什么关联与区别。如果正文大量出现「详情参见某某资料」而没有自己的解释，读者会感到割裂。

外部资料只能作为延伸阅读，不能替代讲义自身的解释。

## 核心写作链路

每个重要方法尽量按照以下链路写：

```text
问题场景 → 图形直觉 → 统一符号与公式 → 方法关系 → 附录代码 → 结果解释 → 可复现文献
```

### 问题场景

先说明实证研究中遇到了什么困难。例如：

- 没有政策时处理组会怎样？
- 处理组和对照组政策前水平不同怎么办？
- 政策分批发生时，TWFE 到底在比较谁？
- 协变量很多时，传统控制变量方法是否还能稳定工作？

方法不能凭空出现。每个方法都应该从一个真实问题长出来。

### 图形直觉

图形负责让读者先看见问题。图形应帮助读者理解比较对象、反事实来源、有效比较、识别威胁和估计量权重。图形要简洁、克制、高对比，不在图中写过多结论性文字。正文负责解释图形含义。

### 统一符号与公式

公式负责把直觉变成正式表达。读者将来写论文时，必须能够写出模型、识别假设和目标参数。因此讲义不能只靠图形解释。

公式应使用全书统一符号，尽量避免每章换一套记号。关键符号要反复保持一致，例如：

- $Y_i(1)$、$Y_i(0)$：潜在结果；
- $D_i$ 或 $Treat_i$：处理组；
- $Post_t$：政策后时期；
- $G_i=g$：首次处理时间为 $g$；
- $ATT(g,t)$：组别—时期处理效应；
- $\alpha_i$、$\lambda_t$：个体和时间固定效应。

公式数量不宜过多，但关键模型必须给出。

### 方法关系

每个方法都要讲清楚它和现有方法之间的关系。例如：

- DID 相比前后比较，多了控制组变化；
- SCM 相比 DID，更主动地用 donor pool 加权构造反事实；
- SDID 相比 SCM，进一步给时间维度加权；
- `csdid` 相比 TWFE，先估计 $ATT(g,t)$ 再聚合；
- `drdid` 把结果回归和倾向得分结合起来；
- DDML 把 FWL / partial out 和机器学习估计 nuisance functions 联系起来。

讲义要让读者知道方法谱系，而不是只知道命令名称。

### 附录代码

代码放在附录 Notebook / do-file 中。正文不写成命令教程。

附录代码要回答三个问题：

1. 这个命令的哪个选项对应正文中的哪个对象、假设或目标参数？
2. 代码运行后，核心输出应该如何解释？
3. 这个实操模块和哪些已发表论文或复现包有关？

附录代码不能只堆命令。每段代码前后都要有简短解释。

### 结果解释

运行结果不是只看显著性。要解释估计量对应哪个目标参数，标准误和置信区间如何理解，动态效应图中的 lead / lag 分别意味着什么，不同估计量结果不一致时可能来自目标参数、对照组、权重或识别假设差异。

### 可复现文献

每个重要实操模块最好配 1–2 篇高度相关的已发表论文，优先选择提供 replication package 的文献。

理想学习路径是：

```text
通过图形理解原理
→ 通过公式理解逻辑
→ 通过代码知道怎么做
→ 通过结果解释知道怎么写
→ 通过复现文献进入前沿论文对话
```

## 正文与附录的边界

正文负责解释问题、建立直觉、给出关键公式、比较方法关系、说明适用场景和识别假设、给出方法选择表、用少量经典文献作为案例。

附录负责运行 Stata / R / Python 代码、说明命令选项、展示结果表和图、解释输出、提供可复现文献入口、帮助读者从讲义走向实操。

正文不要大量堆命令，不要大量写「详情参见」，不要用软件选项替代理论解释，不要把方法写成工具清单。

附录不要只放代码没有解释，不要把所有命令都塞进去，不要忽略命令和正文公式的对应关系，不要忽略输出结果的解释。

## 图形与公式的平衡

图形和公式都不可或缺。图形的作用是让学生在课堂上先形成直觉。公式的作用是让学生能够在论文中严谨表达方法、目标参数和识别假设。

如果只有图形，读者理解了直觉，但写论文时会断层。  
如果只有公式，读者在初学阶段会很难进入问题。  
本书应当让图形和公式配合工作。

建议每个核心方法至少包含：

- 一张核心图；
- 一个关键公式；
- 一段方法关系说明；
- 一个实操附录入口；
- 一篇或两篇可复现文献。

## 语言风格

中文表达应直截了当，避免绕行句式。尽量不用半角双引号；需要强调术语时使用中文引号「」。正文标题简短。讲义正文不宜过度口语化，也不宜写成论文综述。

应避免：

- 机械罗列文献；
- 机械罗列命令；
- 大量空泛判断；
- 用外部链接替代自己的讲解。

应优先：

- 以问题引出方法；
- 用图解释比较对象；
- 用公式收束逻辑；
- 用表格帮助选择；
- 用附录落实代码；
- 用复现文献引导深入学习。

## 对后续 AI 的要求

1. 不要把章节写成资料链接清单；
2. 不要把正文写成命令手册；
3. 每个核心方法都要说明问题背景、识别直觉、关键公式、适用条件、方法代价和与现有方法的关系；
4. 所有代码放入附录；
5. 附录代码必须解释命令选项和正文公式的对应关系；
6. 尽量提供可复现文献；
7. 每章都要和前后章节形成清楚接缝；
8. 每章都要服务于政策评估这条主线。
